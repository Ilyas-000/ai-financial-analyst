# Внутренняя классификация категорий расходов

Документ описывает дерево категорий, используемое оператором для агрегирования транзакций по картам и расходов компании-партнёра.

## Корневые категории

В системе используется иерархическое дерево категорий. Корневые категории:

- `travel` — командировки и перемещение (авиа, поезд, такси, отели).
- `food` — питание (рестораны, доставка, продуктовые магазины).
- `office` — обеспечение офиса (аренда, расходники, мебель).
- `it_saas` — SaaS-подписки и облачные услуги.
- `professional_services` — юридические, консалтинговые, аудит.
- `marketing` — реклама, мероприятия, материалы.
- `transport` — наземный транспорт, ГСМ.
- `other` — прочее, не подпадающее под перечисленные.

Каждая корневая категория содержит до 2 уровней дочерних категорий.

## Связь с MCC

Категория транзакции определяется на основе MCC мерчанта по таблице соответствия. Например:

- MCC 4111, 4121 (такси) → `transport.taxi`.
- MCC 5811, 5812, 5813, 5814 (рестораны и фастфуд) → `food.restaurants`.
- MCC 3000–3299 (авиаперевозки) → `travel.air`.
- MCC 7011 (отели) → `travel.lodging`.
- MCC 5734 (компьютерные программы) → `it_saas`.

При отсутствии явного маппинга используется `other`.

## Корректировка категории

В исключительных случаях бухгалтер может вручную перенести транзакцию в другую категорию через интерфейс реестра. Изменение фиксируется в `audit_log`. Массовая ручная переклассификация (более 20 транзакций) требует согласования CFO.

## Категории для отчётности

В квартальном и годовом снэпшотах (`payload_json.breakdown_by_category`) суммы агрегируются по категориям второго уровня. Это даёт компромисс между детализацией и читаемостью.

## Категории-исключения

Категория `other` используется для транзакций, которые не удалось классифицировать. Если её доля в квартале превышает 5% от общего объёма транзакций, в `anomalies` отчёта появляется запись `unclassified_share_high` — повод для бухгалтера пройтись по реестру и при необходимости перенести часть операций в корректные категории.
