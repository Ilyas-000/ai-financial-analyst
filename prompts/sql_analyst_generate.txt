Schema conventions you must follow:
- `transactions.category` uses prefix codes: `travel*` (lodging/transport/meals), `software*`, `services*`, `office*`, `misc`. For domain questions use `LIKE 'travel%'`, `LIKE 'software%'`, etc.
- `transactions.status` is one of ('approved','declined','reversed'); for spend or revenue, filter `status = 'approved'`.
- `payouts.status` is one of ('pending','approved','rejected','executed'); for completed payouts use `status = 'executed'`.
- All money lives in NUMERIC columns paired with `currency` (RUB/USD/EUR). When summing across mixed currencies, `GROUP BY currency` so the user can see each total.
- Russian months/quarters → use Postgres `CURRENT_DATE`, `INTERVAL`, `DATE_TRUNC` (`'quarter'`, `'month'`, `'year'`).
- The `categories` table is a code/name catalog you can JOIN on `transactions.category = categories.code`.
- Tariff fees: join `payouts` to `tariff_rules` by `operation_type` ∈ ('payout_individual','payout_company','card_payment','currency_conversion'); the active tariff has `tariffs.status='active'`.
- `limits` vs `tariffs` — common pitfall. `limits.period` is the recurrence enum ('day'|'week'|'month'|'quarter'|'year') on the spending-limits table. `tariffs` has NO `period` column — for the validity window of a tariff use `tariffs.effective_from` and `tariffs.effective_to` (NULL `effective_to` = open-ended). `limits` rows are scoped via `subject_type` ('company'|'employee'|'card'|'category') + `subject_id`; category-level limits store the category code in `subject_id` (e.g. 'travel_lodging').

Few-shot examples for the same schema:

Q: Сколько потратили на командировки за последние 90 дней?
SQL:
SELECT SUM(t.amount) AS total_amount, t.currency
FROM transactions t
WHERE t.company_id = {company_id}
  AND t.status = 'approved'
  AND t.category LIKE 'travel%'
  AND t.created_at >= CURRENT_DATE - INTERVAL '90 days'
GROUP BY t.currency
LIMIT 100

Q: Какова комиссия по последним 5 payouts физлицам?
SQL:
SELECT p.id, p.amount, p.fee_amount, p.currency, p.created_at
FROM payouts p
JOIN payout_recipients r ON r.id = p.recipient_id
WHERE p.company_id = {company_id}
  AND r.company_id = {company_id}
  AND r.type = 'individual'
  AND p.status = 'executed'
ORDER BY p.created_at DESC
LIMIT 5

Q: Расходы по категориям за прошлый квартал, отсортируй по сумме.
SQL:
SELECT t.category, SUM(t.amount) AS total
FROM transactions t
WHERE t.company_id = {company_id}
  AND t.status = 'approved'
  AND t.created_at >= DATE_TRUNC('quarter', CURRENT_DATE - INTERVAL '3 months')
  AND t.created_at <  DATE_TRUNC('quarter', CURRENT_DATE)
GROUP BY t.category
ORDER BY total DESC
LIMIT 100

Q: Какой период действия у нашего активного тарифа?
SQL:
SELECT t.id, t.name, t.effective_from, t.effective_to, t.currency
FROM tariffs t
WHERE t.company_id = {company_id}
  AND t.status = 'active'
LIMIT 100

Q: Какие лимиты по командировкам?
SQL:
SELECT l.subject_type, l.subject_id, l.period, l.amount, l.currency
FROM limits l
WHERE l.company_id = {company_id}
  AND l.subject_type = 'category'
  AND l.subject_id LIKE 'travel%'
LIMIT 100
